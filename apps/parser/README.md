# @canrush/parser

Парсер цен на энергетические напитки с российских ритейлеров и маркетплейсов:
**Wildberries, Ozon, Пятёрочка, Магнит, Лента**, а также акционных цен десятков
сетей через агрегатор **Едадил** (единственный источник без браузера и антибота).

Сохраняет консолидированный срез в `data/latest.json`, сырые снапшоты каждого
источника — в `data/raw/<source>/<timestamp>.json`, историю за день — в
`data/history/<YYYY-MM-DD>.json`. При временной блокировке источника подмешивает
его товары из предыдущего успешного прогона с флагом `stale: true`, чтобы сайт
не оставался без данных.

## Установка

Из корня репозитория (npm workspaces):

```bash
npm install
npx playwright install chromium   # браузер для Playwright-адаптеров
```

Опционально — использовать установленный Google Chrome вместо бандлового
Chromium (снижает детект автоматизации):

```bash
cp .env.example .env
# раскомментируйте PARSER_BROWSER_CHANNEL=chrome
```

## Команды

Все команды запускаются из `apps/parser/` (или через `npm -w apps/parser ...`).

| Команда                          | Описание                                                        |
| -------------------------------- | --------------------------------------------------------------- |
| `npm run parse`                  | Однократный прогон всех источников из `config/products.json`.   |
| `npm run parse -- --source=ozon` | Прогон только выбранных источников (через запятую).             |
| `npm run schedule`               | Долгоживущий планировщик (`node-cron`, `CRON_SCHEDULE` из .env).|
| `npm run doctor`                 | Диагностика: открывает каждый источник и печатает статус.       |
| `npm run doctor -- --headed`     | То же в видимом браузере.                                       |
| `npm run session:unlock -- --source=<name>` | Ручная разблокировка сессии источника (см. ниже).     |
| `npm test`                       | Unit-тесты (vitest): normalize, storage, parseFeed, challenge.  |
| `npm run build`                  | Сборка TS в `dist/`.                                            |

## Конфигурация `config/products.json`

Общие поля:

- `category` — идентификатор категории (`energy_drinks`).
- `keywords` — список ключевых слов для фидов и запасного поиска.
- `brands` — список брендов для автоопределения (`detectBrand`).

Конфиг каждого источника живёт в `sources.<name>`:

```jsonc
{
  "wildberries": { "query": "энергетический напиток", "maxItems": 200 },
  "ozon":        { "query": "энергетический напиток", "maxItems": 100 },
  "pyaterochka": { "query": "энергетик", "maxItems": 48 },
  "magnit":      { "categoryId": "", "storeCode": "", "maxItems": 36 },
  "lenta":       { "query": "энергетик", "maxItems": 48 },
  "edadeal":     { "query": "энергетик", "regionId": "213", "maxItems": 2000 }
}
```

### Где взять `categoryId` / `storeCode` для Магнита

Адаптер Магнита (`src/adapters/magnit.ts`) ходит в каталог конкретного магазина.
Нужно указать:

1. **`storeCode`** — код магазина доставки. Откройте `https://magnit.ru`,
   выберите город и магазин, затем в URL страницы магазина найдите код
   (например `https://magnit.ru/catalog/?store=NNNN` → `storeCode = "NNNN"`).
2. **`categoryId`** — идентификатор категории «Энергетические напитки».
   Откройте нужную подкатегорию в каталоге и возьмите `id` из URL/ответа
   каталога, либо подсмотрите его в Network-вкладке при открытии категории.

Запишите значения в `config/products.json` → `sources.magnit`.

### Партнёрский фид Ozon (опционально, рекомендуется)

Ozon жёстко блокирует автоматизацию. Вместо браузерного парсинга можно
использовать партнёрский товарный XML/CSV-фид (Admitad, CityAds и т.п.) —
адаптер `src/adapters/ozon.ts` сначала пробует фид, и только при его отсутствии
падает на браузерный intercept.

Чтобы включить фид, задайте URL в `.env`:

```bash
OZON_FEED_URL=https://...admitad.com/.../ozon_products.xml
```

Логика парсинга фида — в `src/feed/ozonFeed.ts` и `src/feed/parseFeed.ts`.

### Едадил — акции ритейлеров через агрегатор (рекомендуется)

Едадил (Yandex) — агрегатор акционных каталогов: Пятёрочка, Магнит, Лента,
Перекрёсток, Дикси, Ашан, Metro и ещё ~30 сетей сами публикуют туда свои акции.
Адаптер `src/adapters/edadeal.ts` ходит в открытый JSON API `search.edadeal.io`
обычным HTTP-запросом — без Playwright, кук и антибота. Это единственный источник,
который работает «из коробки», без `session:unlock`.

Особенности:

- **Только акционные цены** (Едадил = каталоги скидок), а не полный прайс сети.
- Один SKU приходит с офферами по каждой сети — каждый оффер становится отдельным
  `Product` с полями `retailer` («Пятёрочка») и `promoEndsAt` (конец акции).
- Цены по одной сети могут приходить диапазоном (разные магазины) — берём минимум.
- Обычная выдача API ограничена 600 группами. Для полной картины адаптер сначала
  получает справочник брендов, затем разбивает их на безопасные батчи и объединяет
  результаты. На текущих данных Москвы это около 19 последовательных запросов и
  950–1000 уникальных предложений; между запросами есть пауза 800 мс.
- `maxItems` ограничивает итог после дедупликации: `2000` позволяет забрать всю
  доступную сейчас выдачу; уменьшите значение, если нужен только верх поиска.
- Канонический бренд берётся по `brandUuid` из справочника API. Для офферов без
  `brandUuid` и вариантов вроде «Ред Булл» используются глобальные `brandAliases`
  из `config/products.json`; неизвестное, но переданное API название сохраняется.
- Поиск дополнительно ограничен сегментом «Напитки», а изотоники без признаков
  энергетика отбрасываются.
- Город задаётся `regionId` = Yandex geoid: `213` — Москва (по умолчанию),
  `2` — Санкт-Петербург. Для другого города добавьте geoid и слаг URL в
  `KNOWN_LOCALITIES` (`src/adapters/edadeal.ts`) — слаг нужен только для ссылок
  на карточки `edadeal.ru/<город>/metaoffers/<uuid>`.
- Запрещённые `robots.txt` страницы самого `edadeal.ru` (поиск, `/offers/*`) парсер
  не запрашивает; ссылки на карточки — только для людей.

## `session:unlock` — разблокировка сессии

Ритейлеры (Пятёрочка, Лента, WB) защищены антибот-системами и требуют выбора
магазина доставки. Playwright-сессии сохраняются в `apps/parser/.sessions/<source>/`
и переиспользуются между прогонами.

При первом запуске или после истечения сессии источник вернёт статус
`BLOCKED`/`CHALLENGE`. Чтобы разблокировать:

```bash
npm run session:unlock -- --source=pyaterochka
```

Откроется видимый браузер:

1. Пройдите капчу/проверку, если она появилась.
2. Выберите магазин доставки, если каталог этого требует.
3. Убедитесь, что каталог открывается нормально.
4. Вернитесь в терминал и нажмите **Enter**.

Сессия (cookies + storage state) сохранится, и последующие прогоны `npm run parse`
будут использовать её в headless-режиме. Повторяйте процедуру при повторных
блокировках.

## Структура данных

```
data/
├── latest.json              # консолидированный срез для сайта
├── state.json               # состояние источников (lastSuccessAt и т.д.)
├── raw/<source>/<ts>.json   # сырой результат каждого адаптера
└── history/<YYYY-MM-DD>.json# история цен за день
```

`latest.json` имеет формат:

```jsonc
{
  "generatedAt": "2026-08-11T06:00:00.000Z",
  "count": 42,
  "products": [
    {
      "source": "wildberries",
      "sourceId": "123",
      "name": "Red Bull Энергетический напиток 0.355л",
      "brand": "Red Bull",
      "volumeMl": 355,
      "price": 129,
      "oldPrice": 149,
      "currency": "RUB",
      "url": "https://...",
      "imageUrl": "https://...",
      "category": "energy_drinks",
      "fetchedAt": "2026-08-11T06:00:01.000Z",
      "stale": false
    },
    {
      "source": "edadeal",
      "sourceId": "7c5c68a2-ad44-5075-b940-30076daee3a8",
      "name": "Энергетический напиток Flash Up Energy Банан-Фейхоа 450мл",
      "brand": "Flash Up",
      "volumeMl": 450,
      "price": 46.99,
      "currency": "RUB",
      "url": "https://edadeal.ru/moskva/metaoffers/7c5c68a2-...?baseOfferUuid=1bb420c7-...",
      "retailer": "Магнит",
      "promoEndsAt": "2026-09-15T00:00:00.000Z",
      "category": "energy_drinks",
      "fetchedAt": "2026-09-01T06:00:01.000Z"
    }
  ]
}
```

Поля `retailer` и `promoEndsAt` заполняются только агрегаторами (Едадил): для
них `source` — это агрегатор, а сеть, в которой действует цена, — в `retailer`.

Товары из заблокированных источников помечаются `stale: true` и переносятся из
предыдущего успешного прогона (см. `mergeResults` в `src/storage.ts`).

## Архитектура адаптеров

Каждый адаптер реализует интерфейс `SourceAdapter` (`src/adapters/types.ts`):

```ts
interface SourceAdapter {
  fetchPrices(config: SourceQueryConfig): Promise<{
    products: Product[];
    strategyUsed: 'feed' | 'http_api' | 'intercept' | 'in_page_fetch';
  }>;
}
```

Стратегии:

- **`feed`** — партнёрский XML/CSV-фид (Ozon через `OZON_FEED_URL`).
- **`http_api`** — открытый JSON API источника обычным HTTP-запросом, без браузера
  (Едадил, `search.edadeal.io`).
- **`intercept`** — Playwright перехватывает JSON-ответы API сайта (Wildberries).
- **`in_page_fetch`** — Playwright выполняет `fetch` внутри страницы с cookies
  пользователя (Пятёрочка, Магнит, Лента).

Робототехника уважается через `src/robots.ts`. Антибот-детект и ожидание
челленджа — в `src/browser/challenge.ts`. Сессии — в `src/browser/session.ts`.

## Источники состава и Tavily

Отдельный исследовательский сборщик, не меняет цены, `latest.json` или каталог сайта.
Реестр потенциальных источников: `config/ingredient-sources.json`. Для каждого указаны
домен, разрешённые пути карточек, рынок RU/BY, способ получения, примеры и результаты проверок.
Список источников не означает гарантию полноты или точности состава.

Из корня репозитория:

```bash
npm run ingredients -- --list
npm run ingredients -- --url=https://edostavka.by/product/1810707 --budget=0
npm run ingredients -- --query="Flash Up Банан Фейхоа 450 мл состав" --source=baltika,okolo,magnit --limit=3 --budget=6
npm run ingredients -- --url=https://magnit.ru/product/1000315358 --budget=1
```

`TAVILY_API_KEY` хранится в игнорируемом `apps/parser/.env.local` (или переменной окружения).
Сборщик также читает `apps/parser/.env`, но существующее окружение имеет приоритет.
Не передавайте ключ в аргументах команд. Для прямого HTTP ключ не нужен.

- `--url` проверяет одну известную карточку. Если состав не найден, `--query` запускает поиск.
- `--query` без URL ищет карточки через Tavily только в выбранных доменах реестра.
- HTTP-источники сначала читаются напрямую; при отсутствии состава вызывается Tavily Extract.
  Для источника со стратегией `tavily` сразу используется Extract.
- `--budget=0` полностью отключает Tavily. По умолчанию максимум 6 резервируемых кредитов,
  допустимо 0–20. Basic Search и одноадресный Basic Extract резервируют по 1 кредиту
  **до** запроса, включая ошибки. Фактический расход `usage.credits` выводится отдельно.
- `--limit=3` ограничивает число карточек, включая переданный URL; максимум 10.
- Robots проверяется перед прямым запросом и Extract. При запрете или недоступности robots
  запрос карточки пропускается. Между запросами не менее 3 секунд; автоматических повторов,
  обхода капчи и переходов на неизвестные домены нет.
- Успешные кандидаты кешируются на 30 дней, поиск — на 7 дней. `--refresh` повторяет сбор.
  Неудачное обновление не удаляет предыдущий успешный кеш.

Отчёты: `data/ingredients/runs/<дата>/report.json`, рядом исходный извлечённый текст.
Кеш: `data/ingredients/cache/`. Все данные игнорируются Git.
Результат имеет статус `needs_review` или `missing`, URL источника, рынок, дату и предупреждения.
Запрос — только поисковая подсказка: соответствие бренда, вкуса, объёма и версии **не подтверждается автоматически**.
Состав не генерируется нейросетью, обрывки и подозрительные числа не исправляются догадками.
Состав для BY не переносится автоматически на российские товары.
Привязка к товарам сайта выполняется отдельной командой после проверки, см. ниже.
Код завершения 0 — есть кандидаты, 2 — подходящих составов не найдено, 1 — ошибка запуска.

Для добавления источника внесите карточку в JSON-реестр с точным HTTPS-доменом и путями,
проверьте robots, затем выполните пробный запуск с `--budget=0`. Стратегию `tavily`
используйте только после проверки извлечения; не добавляйте Едадил как источник состава.


### Передача составов на сайт

`npm run ingredients:publish` из корня собирает `apps/site/data/ingredients.json`.
Команда не обращается к Tavily и не тратит кредиты. Сайт читает этот срез на сервере;
ключ API и исходные отчёты в браузер не передаются.

Для добавления состава проверьте точную версию в сохранённом отчёте и внесите запись
в `config/ingredient-products.json`: бренд и канонический вкус каталога, полное название,
объём, идентификатор неизменяемого отчёта, URL и SHA-256 точной строки `ingredients`.
Хэш фиксирует рассмотренный текст: новый результат парсинга сам по себе его не заменяет.
Одна привязка на пару бренд/вкус. Текст отображается как сведения источника, а не как
подтверждённая производителем рецептура. Для BY сайт явно показывает рынок Беларуси.

Экспорт проверяет наличие товара и объёма в каталоге, совпадение источника, рынка и хэша,
отсеивает обрывки и конфликты сахара. Для предварительной публикации неполного перечня
нужно явно указать `status: "unverified"` и непустой `reviewNote` (до 500 символов),
объясняющий ограничение. Это разрешает неполный текст, но не отменяет проверку версии,
источника и хэша; конфликты сахара и неясные границы раздела по-прежнему блокируются.
На сайте все составы из источников помечаются «Состав не подтверждён»: совпадение с
карточкой магазина не означает сверку с этикеткой. Для `unverified` рядом показывается
конкретный `reviewNote`. Состав другого вкуса и случайная поисковая выдача не публикуются.
При любой ошибке существующий срез сохраняется.
Исходные отчёты и каталог нужны на машине экспорта; они игнорируются Git. На сервер сайта
передаётся только итоговый `apps/site/data/ingredients.json`, рядом с `catalog.json`.
В standalone-сборку срез включается через outputFileTracingIncludes: синхронизируйте его
**до** `npm run build`. При обновлении без пересборки заменяйте срез в каталоге data
работающего приложения. При отсутствии или повреждении среза сайт показывает пустое состояние.
