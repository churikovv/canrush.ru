# Парсер CanRush

Основной источник цен — Едадил, HTTP API без браузера. Пятёрочка, Магнит, Лента и другие сети приходят через поле `retailer` в его предложениях. Цены акционные.

Второй источник — Яндекс Лавка (`source: 'lavka'`, `retailer: 'Яндекс Лавка'`), полный прайс «большой лавки» (супермаркет) в городах из `sources.lavka.cities` (сейчас Москва и Петербург). Один GET страницы `/supermarket/catalog/technical/category/energy_beer` на город, без браузера: каталог берётся из SSR-скрипта `storedehydratedstate-data`, точка доставки — cookie `lastGeoCoordinate` с координатами города. В каталог попадают только подразделы «Энергетики…». `/api/` Лавки закрыт в robots.txt и не используется; headless-браузеры Лавка блокирует. Сбой Лавки не роняет город: остаются прошлые цены Лавки с пометкой stale.

## Запуск из корня

```sh
npm install
npm run build
npm run parse -- --cities=all
npm run parse -- --cities=moscow,saint-petersburg
npm run parse -- --source=edadeal
npm run schedule
npm -w apps/parser run download-images
npm -w apps/parser run download-icons
```

`--force` обновляет региональные снимки до истечения срока кэша. Планировщик по умолчанию обходит все 16 городов ежедневно в 06:00 Europe/Moscow (`CRON_SCHEDULE`).

Конфигурация брендов, вкусов и Едадила: `config/products.json`. Снимки городов: `data/regions/<city>/latest.json`; каталог сайта: `apps/site/data/regions/<city>.json`. Кэш цен живёт 6 часов, повтор после ошибки — через 30 минут. Изображения и логотипы повторно используются из дискового кэша.

Сохраняются robots.txt, пауза 800 мс между запросами Едадила, последовательный обход городов и stale-фоллбэк. Сетевые ошибки не повод обходить ограничения источника. Уведомления об ошибках: `TG_BOT_TOKEN`, `TG_CHAT_ID` в локальном `.env`.

Браузерные адаптеры, партнёрские фиды и команды `doctor`/`session:unlock` удалены. Старые имена источников в общих типах оставлены для чтения исторических данных; запуск этих источников запрещён. Playwright используется только как инструмент проверки сайта при разработке.

Команды `ingredients` и `ingredients:publish` для обработки составов сохранены.

### Обновление составов

Составы собираются отдельно от цен, только с явным разделом «Состав». Запрос не публикует результат автоматически:

```sh
npm -w apps/parser run ingredients -- --query="Red Bull Sugarfree 250 мл состав" --limit=3 --budget=4
```

Кэш успешных карточек используется 30 дней, поисковых запросов — 7 дней. `--refresh` повторно проверяет источник, `--budget=0` отключает Tavily. Отчёты и исходный текст сохраняются в игнорируемой папке `data/ingredients/runs/`.

После проверки названия, конкретной версии, объёма и текста обновите `config/ingredient-products.json`: актуальный ключ бренда/вкуса из каталога, `reportId`, URL и SHA-256 точного текста состава. Original, Sugarfree и вкусовые версии — отдельные привязки. `unknown` и `unresolved:` публиковать нельзя. При недоступности источника сохранённая запись сохраняет прежнюю дату получения; неполный перечень требует `status: unverified` и пояснения.

```sh
# Для текущего volume сайта
npm -w apps/parser run ingredients:publish
# Для доставки через Git и следующую сборку сайта
npm -w apps/parser run ingredients:publish -- --bundled
```

Публикация проверяет привязки по каталогам всех городов, уникальность пары бренд/вкус и соответствие текста выбранному отчёту. При ошибке предыдущий файл остаётся целым. В Git добавляются конфигурация привязок и `apps/site/src/content/ingredients.json`, но не сырые отчёты. На VPS не нужно повторять сбор: достаточно обновить Git и пересобрать `site`. Если в volume уже есть `data/ingredients.json`, он имеет приоритет над встроенным срезом.

### Пищевая ценность через GigaChat

Таурин, кофеин, калории, белки, жиры, углеводы и сахар на 100 мл (или 100 г) берутся из того же сохранённого текста страницы, что и состав привязки. GigaChat только переносит числа в JSON; на сайт попадает лишь то, что стоит вплотную к своей подписи в тексте («14Углеводы», «Углеводы⏎11.3», «таурин (230 мг»). Выдуманное, пересчитанное или взятое из другой строки отбрасывается, а «на 100 г / 100 мл» определяется по тексту.

```sh
npm -w apps/parser run ingredients:nutrition            # все привязки; сохранённые ответы модели только перепроверяются
npm -w apps/parser run ingredients:nutrition -- --product=Burn/tropical --refresh
npm -w apps/parser run ingredients:publish -- --bundled # добавить данные к составам сайта
```

Нужен `GIGACHAT_AUTH_KEY` в `.env` (постоянный Authorization key; токен на 30 минут клиент получает сам и обновляет за минуту до конца или после 401). Сервер GigaChat подписан корнем НУЦ Минцифры: `certs/russian_trusted_root_ca.pem` используется только для этих запросов, системное хранилище не трогается. Модель по умолчанию — `GigaChat-2-Pro` (базовая путала строки таблицы), меняется через `GIGACHAT_MODEL`. Ответы и проверка лежат в игнорируемом `data/ingredients/nutrition.json`; публикация берёт данные, только если они получены со страницы текущей привязки.

### Состав и пищевая ценность из Яндекс Лавки

Временный источник до ручной сверки: карточки большой Лавки для товаров из последнего регионального прогона (бренд и вкус уже сопоставлены парсером цен).

```sh
npm -w apps/parser run ingredients:lavka                # кэш 30 дней; --refresh перезапрашивает
npm -w apps/parser run ingredients:publish -- --bundled
```

Карточка `/supermarket/good/<deepLink>` отвечает 404, но отдаёт SSR-состояние товара — решает состояние, а не статус. КБЖУ берутся из полей `options.ingredients.pfcTraits` (на 100 г), состав — из блока «Полный состав» (`ingredientsLoc`); «Краткий состав» Лавка генерирует ИИ (`aiIngredients`) — его не берём. Таурин и кофеин — `compositionDose`: только с единицей (мг, г, % = г на 100 г) и одним значением. GigaChat здесь не нужен. Обход: robots.txt, 3 с + разброс между запросами, остановка на 401/403/429 и капче. Записи Лавки публикуются только для товаров без проверенной привязки, со статусом `unverified` и пояснением; проверенные составы они не перезаписывают.

### Составы от ИИ (последний вариант)

Для товаров без проверенной привязки и без карточки Лавки GigaChat пишет состав и числа по памяти, по названию товара из магазина. На сайте такие записи — `status: ai_generated` с плашкой «Сгенерировано ИИ», без ссылки на источник и **только перечень ингредиентов**: числа модели остаются в `data/ingredients/ai.json` и не публикуются (в прогоне большинство брендов получили одни и те же значения — таурин 80 мг, 23–31 ккал). Любой источник (привязка или Лавка) заменяет их при следующей публикации.

```sh
npm -w apps/parser run ingredients:ai -- --control=10   # слепая проверка на товарах с известными данными, ничего не публикует
npm -w apps/parser run ingredients:ai -- --limit=50
npm -w apps/parser run ingredients:publish -- --bundled
```

Модель может ответить «не знаю»; отбрасываются неправдоподобный перечень, числа вне `NUTRITION_RANGES`, «сахар» в составе версии без сахара и сладкие числа у неё. Контроль 21 октября 2026 (GigaChat-2-Pro, 10 товаров): ±15% совпали 14 из 33 чисел, калорийность занижалась в разы (Burn 60→23, Adrenaline Rush 54→13), перечень совпадал на 20–54% слов — см. `data/ingredients/ai-control.json`.

### Исправление идентичности напитков в сохранённых данных

После обновления правил вкусов выполните сборку и `node apps/parser/dist/index.js reindex-catalog` из корня репозитория. Команда пересобирает региональные и основной каталоги из сохранённых названий, без запросов к магазинам и повторного скачивания изображений. Запускайте её между прогонами парсера.

Смеси вкусов и версии без сахара имеют отдельные ключи. Нераспознанные предложения получают стабильный `unresolved:`-ключ по источнику, ID и названию вместо общей группы `unknown`. Сайт не принимает оценки таких предложений. Старые отзывы `unknown` сохраняются в прежней карточке без автоматического переноса на предполагаемый вкус. Обложка распознанного напитка берётся из общего каталога идентичностей и не меняется при выборе города.

Бренды `Volt`/`Volt Energy`, `Flesh`/`Flash Up` и варианты `Adrenaline` приводятся к `Volt Energy`, `Flash Up`, `Adrenaline Rush`. Явный бренд в названии предложения имеет приоритет над ошибочным полем магазина. Именованные линейки распознаются в `src/product-lines.ts`: например, Game Fuel остаётся самостоятельной карточкой внутри Adrenaline Rush, даже если магазин не указал вкус. Неизвестные линейки и предложения «в ассортименте» не приравниваются к оригиналу.
